PROBLEM 6: Guru Meditation Error (Abstürze bei schnellen WASD-Befehlen)
================================================================================

User: "Guru Meditation Error: Core 1 panic'ed"
"wenn ich schnell auf wasd tippe und dann viele befehle schicke"

Erster Crash (Debug exception/BREAK instr):
- WDT-Timeout bei 10s zu kurz
- NVS-Schreibzugriffe (prefs.begin/putFloat/end) blockierten die loop()
- LÖSUNG: WDT auf 20s erhöht

Zweiter Crash (IntegerDivideByZero bei KEYS:0110/KEYS:0010):
Backtrace zeigte auf setMotorSpeed()
Ursache: Bei actualSpeed zwischen 0.5 und 2.0 ergab
static_cast<uint32_t>(actualSpeed) = 0 (Float-Truncation)
→ STEP_PERIOD_US / 0 = Division durch Null

LÖSUNG:
    // ALT (crash):
    uint32_t interval = STEP_PERIOD_US / static_cast<uint32_t>(actualSpeed);
    
    // NEU (sicher):
    uint32_t actualSpeedInt = static_cast<uint32_t>(actualSpeed);
    if (actualSpeedInt < 1) actualSpeedInt = 1;
    interval = STEP_PERIOD_US / actualSpeedInt;
    
Weiterer Fix: interval > MAX_STEP_INTERVAL setzte auf 0, was später erneut
Division durch Null bei fracAdd auslöste.
Geändert von: if (interval > MAX_STEP_INTERVAL) interval = 0;
Geändert zu:  if (interval > MAX_STEP_INTERVAL) interval = MAX_STEP_INTERVAL;

NVS-Entkopplung (Crash-Prävention):
- Einführung von configDirty Flag (bool)
- handleCommand() schreibt nicht mehr direkt in NVS, sondern setzt nur Flag
- saveConfigIfDirty() wird in loop() im Leerlauf aufgerufen
- validateConfig() durch saveConfigIfDirty() ersetzt

================================================================================
PROBLEM 7: Alle Modi + Farbsensor funktionieren nicht nach Absturz-Fix
================================================================================

User: "perfekt es stürtzt nicht mehr ab aber alle andere modis sowie der farbsensor
       funktionieren nicht"

Ursache: ServerCallbacks (onConnect/onDisconnect) enqueuten keine Events mehr
in bleEventQueue. Dadurch:
- deviceConnected blieb immer false
- sendColorToWebsite() wurde nie aufgerufen (prüft deviceConnected)
- Farbsensor-Daten wurden nie per BLE gesendet
- Alle Spielmodi erhielten keine Farbdaten

LÖSUNG (Code in Edu_V1.3.cpp, Zeilen 495-508):
class ServerCallbacks : public BLEServerCallbacks {
  void onConnect(BLEServer* server) override {
    BleEvent evt = { BLE_EVT_CONNECTED, "" };
    if (bleEventQueue) xQueueSend(bleEventQueue, &evt, 0);
  }
  void onDisconnect(BLEServer* server) override {
    BleEvent evt = { BLE_EVT_DISCONNECTED, "" };
    if (bleEventQueue) xQueueSend(bleEventQueue, &evt, 0);
    server->getAdvertising()->start();
  }
};

Zusätzlich: server->getAdvertising()->start() in onConnect() entfernt
(Advertising während Verbindung gestartet = Fehler).
